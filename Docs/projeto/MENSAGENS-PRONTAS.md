# Mensagens prontas — copie e adapte no Cursor

> Textos para **primeira mensagem**, pedido à TI e confirmação do SPEC. Substitua os colchetes `[...]`.

---

## 1. Primeira mensagem — dashboard

```
Tenho uma ideia de dashboard para [ÁREA]: [2–3 frases do problema que você quer resolver].

Este repositório é a CÓPIA do template BPM (não é o molde oficial projeto-padrao-bpm).
Quero começar pela entrevista em Docs/entrevista/INTERVIEW.md — cenário dashboard —
sem escrever código ainda. Uma pergunta por vez.
```

---

## 2. Primeira mensagem — sistema interno

```
Preciso de um sistema interno para [ÁREA] que [descreva em 2–3 frases: quem usa, o que faz].

Repo: cópia do template BPM. Processo: entrevista → SPEC → aprovação TI → código.
Leia Docs/entrevista/INTERVIEW.md e o cenário sistema-interno. Não implemente nada ainda.
```

## 3. Primeira mensagem — landing page

```
Quero uma landing page para [evento/campanha/produto]: [objetivo em 1–2 frases].

Template BPM — cenário landing-page em Docs/entrevista/scenarios/landing-page.md.

```

## 4. Pedido à TI — criar repositório

**Assunto:** Novo projeto interno — [Nome do sistema]

```

Nome sugerido: [ex.: dashboard-comercial-2026]
Área: [comercial / produção / RH]

Quem vai usar: [perfis / quantidade aproximada]

Podem criar um repositório privado a partir do molde projeto-padrao-bpm
e me dar acesso? Prefiro o Caminho 1 do guia COMO-CRIAR-SEU-PROJETO.

Obrigado(a),
[Nome]
```

## 5. Confirmação do SPEC (para a IA)

```
Li o SPEC.md. Confirmo o escopo da V1 com estas observações:
- [opcional: ajuste 1]
- [opcional: ajuste 2]

Pode considerar o SPEC confirmado do meu lado.
Aguardo aprovação da TI antes de implementar (Docs/projeto/APROVACAO-TI.md).
```

---

## 6. Após aprovação TI — iniciar implementação

```
TI aprovou o desenvolvimento (APROVACAO-TI concluída).
Implemente a V1 conforme SPEC.md usando Docs/skills/INCREMENTAL.md —
um passo por vez, aguardando minha confirmação entre etapas.
```

---

## 7. Pedido de revisão

```
A V1 está funcional localmente. Faça revisão conforme Docs/skills/CODE-REVIEW.md
e liste pontos de atenção antes de considerarmos homologação.
```

---

## O que NÃO colar na primeira mensagem

- “Implementa tudo agora”
- “Igual ao sistema X da concorrência”
- “Já com TOTVS, login AD e deploy em produção”
- Pedidos para commitar no molde oficial `projeto-padrao-bpm`
